# Materialized View (物化视图)

### 📌 名词定义

Materialized View（物化视图）是指**预先计算并存储的查询结果。通过消耗存储空间和更新成本，换取极致的查询性能。是 Stream → Table 转换的典型实现。**

### 🧠 第一性原理

"空间换时间。"
复杂查询（如聚合、JOIN）每次都实时计算太慢，能否提前算好存起来？
**本质策略：通过预计算和持久化，将查询时间复杂度从 O(N) 降到 O(1)。**

### 🛠️ 落地实现（典型应用）

```
Materialized View 的核心应用：

1. 数据库物化视图
   - 预计算并存储复杂查询的结果
   - 例如：SELECT department, COUNT(*), AVG(salary) FROM employees GROUP BY department
   - 查询时直接读取物化视图，无需实时计算
   - 需要定期刷新（Refresh）保持数据新鲜

2. Elasticsearch 倒排索引
   - 预先计算每个词项出现在哪些文档中
   - 查询时直接查倒排索引，无需全量扫描
   - 写入时需要构建倒排索引，写放大较高

3. Redis 缓存
   - 将热点查询结果缓存到 Redis
   - 查询时直接读取缓存，无需查数据库
   - 需要处理缓存一致性问题

4. 流处理中的物化视图
   - Kafka Streams / Flink：将 Stream 物化为 Table
   - 例如：实时计算订单总数，物化为一个计数器
   - 每次事件到来时更新物化视图

5. 核心挑战
   - 数据新鲜度：物化视图的数据可能过期
   - 更新成本：基表数据变更时，需要更新物化视图
   - 存储成本：物化视图占用额外存储空间

6. 典型策略
   - 全量刷新：定期重新计算整个物化视图
   - 增量刷新：只更新变更的部分
   - 实时刷新：基表变更时立即更新物化视图
```

### ⚖️ 架构权衡

- **优点**：查询性能极高（O(1)）；适合复杂查询和聚合操作。
    
- **缺点**：占用额外存储空间；更新成本高；数据可能过期。
    
- **大厂实践**：Elasticsearch 通过倒排索引实现物化视图；Redis 缓存热点查询结果；数据库通过物化视图加速复杂查询；流处理系统通过物化视图实现实时聚合。
