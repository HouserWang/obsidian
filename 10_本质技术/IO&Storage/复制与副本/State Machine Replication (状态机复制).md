# State Machine Replication (状态机复制)

### 📌 名词定义

State Machine Replication（状态机复制）是指**一种多副本一致性方法。多个副本从相同初始状态开始，按相同顺序执行相同操作，达到一致状态。是实现强一致性的核心方法。**

### 🧠 第一性原理

"相同顺序 + 相同操作 = 一致状态。"  
如果多个副本从相同的初始状态开始，按相同的顺序执行相同的操作序列，最终状态必然一致。  
**本质数学：确定性状态机的性质，保证多副本的一致性。**

### 🛠️ 落地实现（核心机制）

```
State Machine Replication 的核心机制：

1. 核心流程
   - 所有副本从相同的初始状态开始
   - Leader 接收写操作，生成操作日志
   - 日志通过共识算法（Raft/Paxos/ZAB）复制到所有副本
   - 所有副本按相同顺序执行相同的操作
   - 最终所有副本达到一致状态

2. 典型应用
   - Raft (etcd, TiKV)：通过多数派提交保证强一致
   - ZAB (ZooKeeper)：类似 Raft，但使用 ZAB 协议
   - Paxos (Google Chubby)：经典的共识算法

3. 与其他概念的关系
   - 依赖 [[Append-Only Log (仅追加日志)|Append-Only Log]] 记录操作序列
   - 通过共识算法保证日志的顺序和一致性
   - 是 [[CP System (CP 系统)|CP 系统]] 的核心实现机制

4. 核心优势
   - 强一致性：所有副本状态完全一致
   - 容错性：少数副本故障不影响整体服务
   - 可证明：基于确定性状态机的数学性质

5. 核心挑战
   - 性能瓶颈：所有写操作必须经过 Leader
   - 延迟：多数派提交增加延迟
   - 可用性：网络分区时少数派不可用
```

### ⚖️ 架构权衡

- **优点**：强一致性保证；容错性好，少数副本故障不影响服务；数学上可证明正确性。
    
- **缺点**：性能瓶颈在 Leader；多数派提交增加延迟；网络分区时少数派不可用。
    
- **大厂实践**：etcd、ZooKeeper、TiKV 都通过状态机复制实现强一致的分布式协调服务。
