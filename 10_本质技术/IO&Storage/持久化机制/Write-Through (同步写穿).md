# Write-Through (同步写穿)

### 📌 名词定义

Write-Through（同步写穿）是指**一种写入传播策略。数据同时写入当前层级和下一层级（如缓存和数据库），等待两者都完成后才返回成功。保证强一致性，但性能较低。**

### 🧠 第一性原理

"同时写，等完成。"  
缓存和数据库之间的数据一致性如何保证？  
**本质策略：通过同步写入两级存储，保证缓存和数据库的数据始终一致。**

### 🛠️ 落地实现（核心机制）

```
Write-Through 的核心机制：

1. 缓存场景
   - 写入缓存的同时，同步写入数据库
   - 等待两者都完成后才返回成功
   - 保证缓存和数据库的数据始终一致

2. 存储场景
   - 写入内存的同时，同步写入磁盘
   - 类似同步刷盘（Sync Flush）
   - 保证内存和磁盘的数据始终一致

3. 典型应用
   - 数据库缓存：写入缓存的同时写入数据库
   - 多级存储：写入内存的同时写入磁盘
   - 分布式缓存：写入本地缓存的同时写入远程存储

4. 对比 [[Write-Behind (异步写回)|Write-Behind]]
   - Write-Through：同步写两级，强一致，性能低
   - Write-Behind：先写当前层，异步写下一层，高性能，可能丢数据

5. 核心优势
   - 强一致性：两级数据始终一致
   - 简单：无需额外的同步机制
   - 安全：断电不丢数据
```

### ⚖️ 架构权衡

- **优点**：强一致性保证；实现简单；数据安全。
    
- **缺点**：性能低（需要等待两级存储都写入完成）；写入延迟高。
    
- **大厂实践**：数据库缓存、多级存储系统广泛使用 Write-Through 策略，保证数据一致性。
