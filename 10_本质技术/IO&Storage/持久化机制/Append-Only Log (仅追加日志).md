# Append-Only Log (仅追加日志)

### 📌 名词定义

Append-Only Log（仅追加日志）是指**一种数据记录方式。数据只能追加到末尾，不能修改或删除已有记录。保留完整的历史记录，是复制、回放、审计和时间旅行的基础。**

### 🧠 第一性原理

"只加不改，保留历史。"  
修改和删除操作会丢失历史信息，且随机写性能差。  
**本质优势：顺序追加写磁盘，性能极高；保留完整历史，支持回放和审计。**

### 🛠️ 落地实现（典型应用）

```
Append-Only Log 的核心应用：

1. Kafka Segment
   - 每个 Partition 由多个 Segment 文件组成
   - 消息只能追加到 Segment 末尾
   - 消费者通过 Offset 定位消息位置
   - 支持消息回放（重新消费历史消息）

2. MySQL Binlog
   - 记录所有数据变更操作
   - 只能追加，不能修改
   - 用于主从复制和崩溃恢复
   - 支持时间点恢复（PITR）

3. Raft Log
   - 共识算法的日志记录
   - 每条日志代表一个状态变更
   - 通过日志复制实现状态机复制

4. 与其他概念的关系
   - Append-Only Log 是 [[WAL (预写式日志)|WAL]] 的实现方式之一
   - [[State Machine Replication (状态机复制)|State Machine Replication]] 依赖 Append-Only Log 记录操作序列
   - 流处理系统（如 Kafka）以 Append-Only Log 为核心抽象

5. 核心优势
   - 顺序写：性能极高，远超随机写
   - 不可变：保留完整历史，支持回放
   - 简单：无需复杂的并发控制
```

### ⚖️ 架构权衡

- **优点**：顺序写性能极高；保留完整历史，支持回放和审计；实现简单，无需并发控制。
    
- **缺点**：日志文件无限增长，需要定期清理；无法直接修改或删除数据。
    
- **大厂实践**：Kafka、MySQL Binlog、Raft Log 都以 Append-Only Log 为核心，是分布式系统和流处理的基础。
