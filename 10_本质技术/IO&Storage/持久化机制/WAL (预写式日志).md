# WAL (预写式日志)

### 📌 名词定义

WAL (Write-Ahead Log，预写式日志) 是指**一种崩溃恢复机制。修改数据前，先将操作记录到持久化日志中，保证系统崩溃后能恢复数据。核心原则：先写日志，后改数据。**

### 🧠 第一性原理

"先记账，后干活。"
系统随时可能崩溃（断电、进程被杀），如何保证数据不丢失？
**本质策略：通过日志的持久性（顺序写磁盘，极快）来保证数据的持久性，即使内存数据丢失，也能通过日志恢复。**

### 🛠️ 落地实现（典型应用）

```
WAL 的核心应用：

1. MySQL Redo Log
   - 事务提交前，先写 Redo Log
   - 崩溃恢复时，通过 Redo Log 重做已提交但未落盘的事务
   - 保证已提交事务的数据不丢失（Durability）

2. PostgreSQL WAL
   - 所有数据修改先写 WAL 日志
   - 通过 WAL 实现崩溃恢复和主从复制
   - 从库通过读取主库的 WAL 实现数据同步

3. Redis AOF (Append-Only File)
   - 每条写命令追加到 AOF 文件
   - 崩溃恢复时，重放 AOF 文件恢复数据
   - 支持 everysec、always、no 三种刷盘策略

4. 核心机制
   - 顺序写：日志追加写入，性能极高
   - 崩溃恢复：通过日志重做（Redo）恢复数据
   - 持久性保证：已提交事务的数据绝不丢失

5. 与其他概念的关系
   - WAL 通常使用 [[Append-Only Log (仅追加日志)|Append-Only Log]] 方式实现
   - [[Flush Strategy (刷盘策略)|刷盘策略]]是 WAL 的具体实现机制
   - [[State Machine Replication (状态机复制)|State Machine Replication]] 依赖 WAL 记录操作序列
```

### ⚖️ 架构权衡

- **优点**：保证数据持久性，崩溃后可恢复；顺序写磁盘，性能极高。
    
- **缺点**：日志文件会无限增长，需要定期清理；恢复过程可能耗时较长。
    
- **大厂实践**：MySQL、PostgreSQL、Redis 都通过 WAL 保证数据持久性，是数据库系统的基石。
