# Compensating Transaction (补偿事务)

### 📌 名词定义

Compensating Transaction（补偿事务）是指**在无法提供分布式事务（如 XA）的系统中，通过逆向操作"撤销"业务影响的模式。是保证最终一致性的经典业务层模式，是 Saga 模式的核心组成部分。**

### 🧠 第一性原理

"先斩后奏，不行再退。"  
分布式事务（2PC/XA）性能差、可用性低，能否用业务层面的"逆向操作"替代技术层面的"全局回滚"？  
**本质设计：每个正向操作都有一个对应的补偿操作，失败时按相反顺序执行补偿，达到业务层面的回滚。**

### 🛠️ 落地实现（核心机制）

```
Compensating Transaction 的核心机制：

1. 基本概念
   - 正向操作：创建订单（INSERT order）
   - 补偿操作：取消订单（UPDATE order SET status='CANCELLED'）
   - 正向操作：扣减库存（UPDATE stock = stock - 1）
   - 补偿操作：释放库存（UPDATE stock = stock + 1）

2. Saga 模式中的补偿
   - 将长事务拆分为多个本地事务
   - 每个本地事务有对应的补偿事务
   - 失败时，按相反顺序执行补偿事务
   - 例如：订单 → 库存 → 积分，积分失败 → 补偿库存 → 补偿订单

3. 典型应用
   - 电商下单：创建订单 + 扣减库存 + 扣减余额，失败时补偿
   - 机票预订：预订机票 → 预订酒店 → 租车，失败时补偿
   - 跨行转账：A 扣款 + B 加款，B 失败时补偿 A

4. 核心挑战
   - 幂等性：补偿操作必须支持幂等，防止重复补偿
   - 空补偿：正向操作还没执行，补偿先到了，必须静默返回成功
   - 悬挂：正向操作延迟，补偿先执行完了，正向操作才到达

5. 对比 2PC
   - 2PC：技术层面的全局回滚，强一致，性能差
   - 补偿事务：业务层面的逆向操作，最终一致，性能好
```

### ⚖️ 架构权衡

- **优点**：性能极高，无需全局锁；支持长生命周期的业务流程；可用性高。
    
- **缺点**：缺乏隔离性，中间状态可见；补偿逻辑复杂，需要处理幂等、空补偿、悬挂等问题。
    
- **大厂实践**：Saga 模式广泛应用于电商、机票预订等长链路流程；阿里巴巴 Seata 提供 Saga 模式支持；蚂蚁金服使用 Saga 处理分布式事务。
