# Pipeline (流水线)

### 📌 名词定义

Pipeline（流水线）是指**一种并发请求模型。发送方发出一个请求后不等回复，立即发送下一个请求，将网络像水管一样填满。通过延迟隐藏（Latency Hiding）极大提升吞吐量。**

### 🧠 第一性原理

"发完就发下一个，别等。"  
传统 Stop-and-Wait 模型：发一个包 → 等 ACK → 再发下一个，大部分时间在空等。  
**本质洞察：网络延迟是固定的，通过并发发送多个请求，将等待时间隐藏，极大提升吞吐量。**

### 🛠️ 落地实现（核心机制）

```
Pipeline 的核心机制：

1. Stop-and-Wait（无 Pipeline）
   - 发送包 A → 等 ACK A → 发送包 B → 等 ACK B
   - 大部分时间在空等 RTT（往返时延）
   - 带宽利用率极低

2. Pipeline（有流水线）
   - 发送包 A → 发送包 B → 发送包 C → 发送包 D
   - 收到 ACK A → 收到 ACK B → 收到 ACK C
   - 虽然每个包的延迟没变，但单位时间内传的包多了（吞吐量巨大）

3. 典型应用
   - RocketMQ DLedger：允许几百个请求同时在网络上"飞"
   - Redis Pipeline：客户端批量发送命令，服务端批量返回
   - HTTP/2 Pipeline：多路复用，多个请求并发发送
   - TCP Pipeline：滑动窗口协议

4. 关键参数
   - 发送窗口（Window Size）：允许同时发送的未确认请求数
   - 窗口越大，吞吐量越高，但可能丢包或乱序
   - RocketMQ：发送窗口几百个请求

5. 对比 Stream
   - Pipeline：并发发包，每个包是独立的请求
   - Stream：字节流直灌，不区分包的边界
```

### ⚖️ 架构权衡

- **优点**：极大提升吞吐量；隐藏网络延迟；带宽利用率高。
    
- **缺点**：需要处理乱序响应；窗口过大会导致丢包或内存压力。
    
- **大厂实践**：RocketMQ DLedger、Redis Pipeline、HTTP/2、TCP 滑动窗口都通过 Pipeline 机制提升吞吐量。
