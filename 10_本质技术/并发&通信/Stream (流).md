# Stream (流)

### 📌 名词定义

Stream（流）是指**一种数据形态。数据像水龙头流出来的字节流，发送方不关心包的边界，接收方自己切分和解析。与 Pipeline（并发发包）相对。**

### 🧠 第一性原理

"不管包，只管流。"  
Pipeline 模型中，每个请求是一个完整的包，需要序列化/反序列化。  
**本质洞察：将数据视为连续的字节流，省去包的边界处理，极致简化协议，提升性能。**

### 🛠️ 落地实现（核心机制）

```
Stream 的核心机制：

1. Packet（包/帧）
   - 一个 RPC 请求是一个完整的包
   - 例如：Raft 的 AppendEntriesRequest，是一个 Java 对象序列化后的独立数据块
   - 需要序列化/反序列化，有额外开销

2. Stream（流）
   - 发送方直接将字节灌入 Socket，不关心包的边界
   - 接收方一边接字节流，一边自己切分"哦，这 100 字节是一条消息"
   - 例如：RocketMQ 4.x 默认 HA，通过 FileChannel.transferTo 直灌

3. 典型应用
   - RocketMQ 4.x 默认 HA：Master 将 CommitLog 字节流直灌给 Slave
   - 文件传输：通过 FileChannel.transferTo 传输字节流
   - 音视频流：实时传输，不区分包的边界

4. 对比 Pipeline
   - Pipeline：并发发包，每个包是独立的请求，需要序列化/反序列化
   - Stream：字节流直灌，不区分包的边界，性能更高

5. 核心优势
   - 性能极高：省去包的边界处理
   - 简单：无需复杂的协议
   - 适合大文件、大数据量传输
```

### ⚖️ 架构权衡

- **优点**：性能极高，省去包的边界处理；实现简单。
    
- **缺点**：接收方需要自己切分字节流，复杂度高；不适合需要严格包边界的场景。
    
- **大厂实践**：RocketMQ 4.x 默认 HA 使用 Stream 模式传输 CommitLog；文件传输、音视频流广泛使用 Stream 模式。
