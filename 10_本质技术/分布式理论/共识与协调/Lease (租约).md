# Lease (租约)

### 📌 名词定义

Lease（租约）是指**一种在分布式系统中用于实现"临时所有权"或"缓存一致性"的带时限锁。中心节点向客户端授予一个有时间期限的权限（如写入权、主节点身份），客户端需定期续租。若租约过期，中心节点可安全地将权限授予其他客户端。**

### 🧠 第一性原理

"权力是有期限的。"
分布式系统中，节点可能随时宕机或网络分区，不能永久持有某种权限。
**本质设计：通过"时间锁"，保证即使客户端僵死，权限也能在租约到期后自动释放。**

### 🛠️ 落地实现（典型应用）

```
Lease 的核心应用：

1. 故障检测与主节点选举
   - Kafka Controller：通过租约管理 DataNode 的存活状态
   - HDFS NameNode：DataNode 定期发送[[Heartbeat Mechanism (心跳机制)|心跳]]续租
   - 若租约过期，判定节点故障，触发[[Failover (故障转移)|故障转移]]

2. 分布式锁
   - ZooKeeper 临时顺序节点：会话结束（租约到期）自动删除
   - etcd Lease API：客户端持有租约，过期自动释放锁
   - 避免了"客户端宕机，锁永远不释放"的问题

3. 本地缓存失效
   - 客户端持有数据的租约，过期后必须从源头重新验证
   - 保证缓存数据不会无限期过期

4. 典型流程
   ```
   Client A 请求锁 → Server 授予租约（TTL=30s）
   Client A 持有锁，定期续租（每 10s 续一次）
   
   场景 1：Client A 正常运行 → 持续续租，一直持有锁
   场景 2：Client A 宕机 → 30s 后租约过期，Server 可将锁授予 Client B
   ```
```

### ⚖️ 架构权衡

- **优点**：解决了网络分区或客户端僵死导致的"[[Brain Split (脑裂)|脑裂]]"或资源永久占用问题；租约总会过期，保证系统自愈能力。
    
- **缺点**：需要维护租约状态，增加服务端负担；续租失败可能导致服务中断。
    
- **大厂实践**：ZooKeeper、etcd 都通过租约机制实现分布式锁和主节点管理，是分布式协调服务的核心原语。
