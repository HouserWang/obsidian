# Vector Clock (向量时钟)

### 📌 名词定义

Vector Clock（向量时钟）是指**一种分布式逻辑时钟机制，通过维护每个节点的版本向量，检测事件之间的因果顺序和并发关系。用于解决"谁先谁后"的问题，是分布式系统中版本冲突检测的核心技术。**

### 🧠 第一性原理

"没有全局时钟，就用相对顺序。"
分布式系统中物理时钟不可靠（时钟漂移、网络延迟），无法依赖时间戳判断事件顺序。
**本质数学：通过向量比较，判断事件是"因果关系"还是"并发关系"。**

### 🛠️ 落地实现（核心算法）

```
Vector Clock 的核心机制：

1. 版本向量表示
   - 每个节点维护一个向量：[N1: 0, N2: 0, N3: 0]
   - 每次写入，对应节点的计数器 +1
   - 例如：节点 A 写入 → [A: 1, B: 0, C: 0]

2. 因果关系判断
   - V1 < V2：V1 的每个分量都 ≤ V2，且至少一个 <
     → V1 发生在 V2 之前（因果）
   - V1 || V2：存在 i, j 使得 V1[i] > V2[i] 且 V1[j] < V2[j]
     → V1 和 V2 并发（冲突）

3. 典型应用
   - Amazon DynamoDB：用 Vector Clock 检测数据冲突
   - Riak 数据库：通过 Vector Clock 实现最终一致性
   - Cassandra：早期版本使用，后改用时间戳

4. 冲突解决
   - 检测到并发（V1 || V2）→ 需要冲突解决
   - [[Conflict Resolution & LWW (冲突解决与最后写入获胜)|Last Write Wins (LWW)]]：比较时间戳，保留最新的
   - 手动合并：人工或业务逻辑决定保留哪个版本
   - [[CRDT (无冲突复制数据类型)|CRDT]]：通过数据结构设计避免冲突
```

### ⚖️ 架构权衡

- **优点**：无需全局时钟，纯逻辑判断；能准确检测因果关系和并发冲突。
    
- **缺点**：向量大小随节点数线性增长（N 个节点需要 N 维向量）；无法处理时钟漂移问题。
    
- **大厂实践**：Amazon DynamoDB 使用 Vector Clock 检测数据版本冲突，结合 LWW 或 CRDT 解决冲突。
