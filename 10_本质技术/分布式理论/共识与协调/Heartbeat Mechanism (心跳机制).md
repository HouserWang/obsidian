# Heartbeat Mechanism (心跳机制)

### 📌 名词定义

Heartbeat Mechanism（心跳机制）是指**节点间定期发送简单信号以宣告存活和传递基本状态的机制。接收方如果在超时时间内未收到心跳，则判定发送方可能故障。是分布式系统故障检测的基础。**

### 🧠 第一性原理

"定期报平安，失联即故障。"
分布式系统中，节点无法直接判断其他节点是"真的故障"还是"网络延迟"。
**本质策略：通过周期性心跳，将"故障检测"转化为"超时判断"。**

### 🛠️ 落地实现（典型应用）

```
Heartbeat 的核心应用：

1. 集群成员管理与故障检测
   - Redis Sentinel：Sentinel 节点间通过 [[Gossip Protocol (流行病协议)|Gossip]] 传播心跳状态
   - Consul：Agent 间通过 Gossip 交换健康信息
   - 超时未收到心跳 → 判定节点故障

2. 数据复制健康度监控
   - MySQL 主从：从库定期向主库发送心跳，报告复制进度
   - Redis 主从：Master 通过心跳监控 Slave 的同步状态

3. 任务调度器与执行器
   - YARN：NodeManager 向 ResourceManager 发送心跳
   - Kubernetes：kubelet 定期向 API Server 报告节点状态

4. 关键权衡
   - 心跳间隔 vs 超时时间
   - 间隔太短：增加网络开销
   - 间隔太长：故障发现延迟高
   - 典型配置：心跳间隔 1-5s，超时时间 10-30s
```

### ⚖️ 架构权衡

- **优点**：实现简单，开销极小（只需发送轻量级信号）；能快速检测节点故障。
    
- **缺点**：无法区分"节点故障"和"网络分区"；心跳风暴可能淹没网络。
    
- **大厂实践**：Redis Sentinel、Consul、Kubernetes 都通过心跳机制实现故障检测，是分布式系统的基础设施。
