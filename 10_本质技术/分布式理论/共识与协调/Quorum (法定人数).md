# Quorum (法定人数)

### 📌 名词定义

Quorum 是指**在分布式系统中，完成某项操作所需的最小节点数（或投票数）。只有当成功响应的节点数达到或超过 Quorum 时，操作才被视为成功。典型公式为 W + R > N（W: 写成功节点数，R: 读成功节点数，N: 副本总数）。**

### 🧠 第一性原理

"少数服从多数。"
分布式系统无法依赖单一节点的判断，必须通过多数派的共识来保证决策的正确性。
**本质数学：通过 W + R > N 的公式，保证读写集合必有交集，从而确保读取到最新数据。**

### 🛠️ 落地实现（典型应用）

```
Quorum 的核心应用：

1. Raft 共识算法
   - [[Leader Election (领导者选举)|Leader 选举]]：候选人必须获得 N/2 + 1 的投票
   - 日志提交：必须复制到 N/2 + 1 个节点
   - 3 节点集群：Quorum = 2，允许挂 1 个节点
   - 5 节点集群：Quorum = 3，允许挂 2 个节点

2. Kafka [[ISR (同步副本列表)|ISR]] 机制
   - min.insync.replicas = 2（最小同步副本数）
   - acks = all：要求 ISR 中所有副本都确认
   - 动态维护 ISR 列表，踢掉慢节点

3. Cassandra 无主复制
   - 读写 Quorum：QUORUM = (replication_factor / 2) + 1
   - 读操作：读取 R 个副本，比较版本号，返回最新
   - 写操作：写入 W 个副本，R + W > N 保证读到最新

4. ZooKeeper
   - 写操作：多数派节点确认才返回成功
   - 选举：候选人必须获得多数派投票
```

### ⚖️ 架构权衡

- **优点**：通过数学公式保证数据一致性，是分布式共识的基石。
    
- **缺点**：Quorum 过大会降低可用性（需要更多节点确认），过小会降低一致性。
    
- **大厂实践**：Etcd/ZooKeeper 使用 3 或 5 节点集群（Quorum = 2 或 3），在可用性和一致性之间取得平衡。
