# Two-Phase Commit (两阶段提交 / 2PC)

### 📌 名词定义

Two-Phase Commit（两阶段提交，简称 2PC）是指**一种[[分布式事务|分布式事务]]协议，通过"准备（Prepare）"和"提交（Commit）"两个阶段，保证跨多个资源管理器（如多个数据库）的分布式事务的原子性。所有参与者要么全部提交，要么全部回滚。**

### 🧠 第一性原理

"要么全做，要么全不做。"  
分布式事务涉及多个独立的资源管理器，如何保证它们要么全部成功，要么全部失败？  
**本质设计：通过一个协调者（Transaction Manager）统一指挥，所有参与者（Resource Manager）在准备阶段确认，在提交阶段执行。**

### 🛠️ 落地实现（核心流程）

```
Two-Phase Commit 的核心流程：

1. 准备阶段（Prepare Phase）
   - 协调者向所有参与者发送 PREPARE 请求
   - 参与者执行事务操作，但不提交
   - 参与者将操作写入日志（Undo Log + Redo Log）
   - 参与者回复 YES（准备成功）或 NO（准备失败）

2. 提交阶段（Commit Phase）
   - 如果所有参与者都回复 YES：
     - 协调者发送 COMMIT 请求
     - 参与者正式提交事务
     - 参与者回复 ACK
   - 如果有任何参与者回复 NO：
     - 协调者发送 ROLLBACK 请求
     - 参与者回滚事务
     - 参与者回复 ACK

3. 核心问题
   - 同步阻塞：参与者在准备阶段阻塞，等待协调者指令
   - 单点故障：协调者宕机，参与者无法继续
   - 数据不一致：提交阶段部分参与者失败，导致数据不一致

4. 典型应用
   - XA 协议：J2EE、.NET 的分布式事务标准
   - Seata AT 模式：阿里巴巴的分布式事务框架
   - 数据库跨分片事务
```

### ⚖️ 架构权衡

- **优点**：保证分布式事务的原子性；实现相对简单，广泛支持。
    
- **缺点**：同步阻塞，性能差；协调者单点故障；提交阶段失败可能导致数据不一致。
    
- **大厂实践**：Seata AT 模式通过改进 2PC（异步提交、自动回滚）提升性能；现代微服务更倾向于使用 [[Compensating Transaction (补偿事务)|Saga 模式]]替代 2PC。
