# CP System (CP 系统)

### 📌 名词定义

CP 系统是指**在 [[CAP Theorem (CAP 定理)|CAP 定理]] 的约束下，选择一致性（Consistency）和分区容错性（Partition Tolerance），放弃部分可用性（Availability）的分布式系统。当发生网络分区时，CP 系统会拒绝部分请求以保证数据的一致性。**

### 🧠 第一性原理

"宁可停机，不可错乱。"  
对于金融、元数据管理等场景，数据的正确性比服务的连续性更重要。  
**本质选择：在"数据错误"和"服务不可用"之间，选择后者。**

### 🛠️ 落地实现（典型代表）

```
CP 系统典型代表：
├── Etcd (Kubernetes 元数据存储)
│   └── 基于 Raft 共识算法，多数派提交才返回成功
├── ZooKeeper (分布式协调服务)
│   └── 基于 ZAB 协议，强一致的元数据存储
├── Consul (服务发现与配置管理)
│   └── 基于 Raft，保证服务注册信息的一致性
└── TiKV (分布式数据库)
    └── 基于 Raft，强一致的 KV 存储

共同特征：
- 写操作必须得到多数派（[[Quorum (法定人数)|Quorum]]）节点的确认
- 网络分区时，少数派分区不可用（拒绝写入）
- 已确认的数据绝不丢失
```

### ⚖️ 架构权衡

- **优点**：数据[[Strong Consistency & Linearizability (强一致性与线性化)|强一致性]]保证，适合存储关键的元数据、配置信息、分布式锁等。
    
- **缺点**：网络分区时可用性下降，少数派节点无法提供服务。
    
- **适用场景**：分布式系统的"大脑"和"真相之源"，如 K8s 的 Etcd、微服务的配置中心。
