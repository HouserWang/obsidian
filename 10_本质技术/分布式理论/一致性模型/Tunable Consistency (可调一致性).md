# Tunable Consistency (可调一致性)

### 📌 名词定义

可调一致性是指**将一致性强度的选择权交给业务方，通过配置参数在"[[Strong Consistency & Linearizability (强一致性与线性化)|强一致]]"和"[[Eventual Consistency (最终一致性)|最终一致]]"之间灵活切换。现代分布式系统的标志性设计，允许业务根据场景需求选择合适的一致性级别。**

### 🧠 第一性原理

"没有银弹，只有权衡。"  
不同的业务场景对一致性的要求不同：金融转账需要强一致，社交动态可以容忍延迟。  
**本质设计：通过参数化配置，让系统在一致性和可用性之间动态权衡，而非硬编码某种固定策略。**

### 🛠️ 落地实现（典型应用）

```
Tunable Consistency 的核心实现：

1. Kafka 的 acks 参数
   - acks=0：生产者不等确认，性能最高，可能丢消息
   - acks=1：Leader 写入即返回，性能与安全的平衡
   - acks=all：[[ISR (同步副本列表)|ISR]] 中所有副本确认，强一致，性能最低

2. Cassandra 的读写级别
   - ONE：只读写一个副本，性能最高
   - [[Quorum (法定人数)|QUORUM]]：读写多数派副本，平衡一致性与性能
   - ALL：读写所有副本，强一致，性能最低
   - 业务方可根据场景动态选择

3. Redis 的 WAIT 命令
   - 默认异步复制，性能极高
   - WAIT numreplicas timeout：等待指定数量的副本确认
   - 在需要强一致的场景临时提升一致性级别

4. MySQL 的复制策略
   - 异步复制：默认，性能最高
   - 半同步复制：至少一个从库确认，向 CP 妥协
   - MGR (Group Replication)：基于 Paxos，强一致
```

### ⚖️ 架构权衡

- **优点**：极度灵活，业务方可根据场景选择最合适的一致性级别，无需为不同场景部署不同的系统。
    
- **缺点**：增加了系统的复杂性，业务方需要理解不同一致性级别的含义和代价。
    
- **大厂实践**：Kafka 的 acks、Cassandra 的 QUORUM 都是可调一致性的经典实现，让业务方在性能与安全之间做出最佳选择。
