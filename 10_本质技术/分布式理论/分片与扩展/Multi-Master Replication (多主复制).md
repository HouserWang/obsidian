# Multi-Master Replication (多主复制)

### 📌 名词定义

Multi-Master Replication（多主复制）是指**有多个主节点，均可写入，然后通过异步方式解决冲突的数据复制模式。每个主节点独立接收写操作，后台通过冲突解决算法（如 [[Conflict Resolution & LWW (冲突解决与最后写入获胜)|Last Write Wins]]、[[CRDT (无冲突复制数据类型)|CRDT]]）保证[[Eventual Consistency (最终一致性)|最终一致性]]。**

### 🧠 第一性原理

"多个老板都能拍板。"  
单主复制的瓶颈在于主节点的写入能力。  
**本质设计：通过多个主节点并行写入，突破单点写入瓶颈，但需要解决写入冲突。**

### 🛠️ 落地实现（核心机制）

```
Multi-Master Replication 的核心机制：

1. 写入流程
   - 客户端向任意主节点写入
   - 主节点本地成功即返回
   - 后台异步将变更复制到其他主节点

2. 冲突解决
   - [[Conflict Resolution & LWW (冲突解决与最后写入获胜)|Last Write Wins (LWW)]]：以时间戳最新的为准
   - [[CRDT (无冲突复制数据类型)|CRDT]]：通过数据结构设计避免冲突
   - 手动合并：人工或业务逻辑决定保留哪个版本
   - [[Vector Clock (向量时钟)|向量时钟]]：检测并发写入，触发冲突解决

3. 典型应用
   - 多数据中心同步：每个数据中心都有自己的主节点
   - 离线优先应用：客户端本地写入，联网后同步到服务器
   - 协同编辑：多个用户同时编辑同一文档

4. 核心挑战
   - 冲突检测：如何发现并发写入
   - 冲突解决：如何合并冲突的写入
   - 写入顺序：不同节点看到的写入顺序可能不同
```

### ⚖️ 架构权衡

- **优点**：写入吞吐量极高，无单点瓶颈；支持多数据中心、离线优先等场景。
    
- **缺点**：冲突解决复杂，可能导致数据丢失或不一致；调试和排查问题困难。
    
- **大厂实践**：CouchDB、Riak 等 NoSQL 数据库支持多主复制，通过 CRDT 或 LWW 解决冲突。
