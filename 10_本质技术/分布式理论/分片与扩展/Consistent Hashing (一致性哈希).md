# Consistent Hashing (一致性哈希)

### 📌 名词定义

Consistent Hashing（一致性哈希）是指**一种特殊的哈希分区策略，在节点增删时，仅需移动最少量的数据，极大减少重新哈希的代价。广泛用于缓存系统、负载均衡和分布式存储。**

### 🧠 第一性原理

"加节点不搬家。"
传统哈希（hash(key) % N）在节点数变化时，几乎所有数据都需要重新映射。
**本质数学：将哈希空间组织成一个环（0 到 2^32-1），数据映射到环上最近的节点，节点增删只影响相邻的一小段数据。**

### 🛠️ 落地实现（核心算法）

```
Consistent Hashing 的核心机制：

1. 哈希环构建
   - 将哈希值空间组织成一个虚拟的环：0 到 2^32-1
   - 对每个节点计算哈希值，映射到环上
   - 对每条数据计算哈希值，映射到环上

2. 数据路由
   - 数据顺时针找到最近的节点，存储在该节点
   - 例如：数据 hash=100，节点 A=50，节点 B=150 → 数据存在 B

3. 节点增删
   - 新增节点 C（hash=120）：只影响 100-120 之间的数据
   - 删除节点 B：只影响 50-150 之间的数据
   - 其他数据不受影响

4. 虚拟节点（解决[[Partition Key & Data Skew (分区键与数据倾斜)|数据倾斜]]）
   - 物理节点少时，哈希分布可能不均匀
   - 为每个物理节点创建多个虚拟节点（如 100 个）
   - 虚拟节点均匀分布在环上，保证数据分布均匀

5. 典型应用
   - Memcached：缓存系统的节点路由
   - DynamoDB：数据分片
   - CDN：负载均衡，将请求路由到最近的边缘节点
   - Nginx：一致性哈希负载均衡
```

### ⚖️ 架构权衡

- **优点**：节点增删时数据迁移量极小；扩展性极强，适合动态集群。
    
- **缺点**：实现复杂度高于普通哈希；虚拟节点增加内存开销。
    
- **大厂实践**：Memcached、DynamoDB、CDN 负载均衡都采用一致性哈希，实现高效的节点路由和数据分布。
