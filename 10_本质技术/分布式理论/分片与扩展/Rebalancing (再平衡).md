# Rebalancing (再平衡)

### 📌 名词定义

Rebalancing（再平衡）是指**当分布式集群中的节点增加或减少时，将数据从现有节点重新分配到新节点的过程。目的是保证数据分布的均匀性和负载均衡。**

### 🧠 第一性原理

"加节点就要搬家。"  
集群扩容或缩容时，数据需要重新分布，否则新节点空闲、旧节点过载。  
**本质挑战：如何在再平衡过程中，最小化数据迁移量，同时保证服务不中断？**

### 🛠️ 落地实现（典型策略）

```
Rebalancing 的核心策略：

1. 哈希分区再平衡
   - 传统哈希：hash(key) % N，节点数变化时几乎所有数据都要迁移
   - [[Consistent Hashing (一致性哈希)|一致性哈希]]：节点增删时，只影响相邻的一小段数据
   - 虚拟节点：通过虚拟节点均匀分布，减少迁移量

2. 范围分区再平衡
   - 按范围分片：新增节点时，将某个分片一分为二
   - 典型应用：HBase、TiDB 的 Region 分裂
   - 优点：支持范围查询；缺点：分裂过程复杂

3. 典型应用
   - Kafka：新增 Broker 时，需要手动触发 Partition 重新分配
   - Redis Cluster：新增节点时，通过 CLUSTER REBALANCE 迁移 Slot
   - Cassandra：新增节点时，通过 [[Gossip Protocol (流行病协议)|Gossip]] 协议自动触发数据迁移
   - Elasticsearch：新增 Data Node 时，Master 自动重新分配 Shard

4. 再平衡的挑战
   - 数据迁移期间的网络开销
   - 迁移过程中的服务可用性
   - 如何保证迁移不丢数据
   - 如何避免迁移过程中的热点问题
```

### ⚖️ 架构权衡

- **优点**：保证集群负载均衡和数据均匀分布；支持水平扩展。
    
- **缺点**：再平衡过程消耗网络带宽和 IO；可能导致短暂的服务性能下降。
    
- **大厂实践**：Kafka、Redis Cluster、Elasticsearch 都支持在线再平衡，通过增量迁移和限流策略，保证再平衡过程对业务影响最小。
