# Partition Key & Data Skew (分区键与数据倾斜)

### 📌 名词定义

Partition Key（分区键）是指**用于决定数据落在哪个分片的键。数据分布的均匀性完全取决于分区键的选择。Data Skew（数据倾斜）是指**某些分片的数据量或访问量远大于其他分片，导致热点问题和性能瓶颈。**

### 🧠 第一性原理

"选对分区键，事半功倍。"  
分区键的选择直接决定了数据分布的均匀性和查询性能。  
**本质问题：如何让数据均匀分布，避免某些分片成为热点？**

### 🛠️ 落地实现（核心策略）

```
Partition Key & Data Skew 的核心机制：

1. 分区键选择原则
   - 高基数（High Cardinality）：分区键的值越多，分布越均匀
   - 避免低基数键：如 status（只有几个值），会导致严重倾斜
   - 典型好的分区键：user_id、order_id、timestamp

2. 数据倾斜的成因
   - 分区键选择不当：如按"省份"分区，某些省份数据量极大
   - 热点用户：某些用户的访问量远超其他用户
   - 时间热点：某些时间段的数据量远超其他时间段

3. 解决数据倾斜的策略
   - 加盐（Salting）：在分区键后添加随机后缀，打散热点
   - 虚拟分区：将热点分片进一步拆分为多个子分片
   - 复合分区键：使用多个字段的组合作为分区键
   - 动态分区：根据数据量动态调整分片数

4. 典型应用
   - Kafka：按 user_id 分区，避免某些 Partition 数据量过大
   - Spark：处理数据倾斜时，对热点 Key 加盐
   - 数据库：按时间范围分区，避免单个分片过大
```

### ⚖️ 架构权衡

- **优点**：合理的分区键选择能极大提升查询性能和数据分布均匀性。
    
- **缺点**：分区键一旦确定，难以更改；数据倾斜问题需要持续监控和优化。
    
- **大厂实践**：Kafka、Cassandra、数据库都通过合理的分区键设计和动态调整策略，避免数据倾斜和热点问题。
