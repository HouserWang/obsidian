# Degradation (降级)

### 📌 名词定义

Degradation（降级）是指**当系统压力大时，主动关闭非核心功能，保证核心功能可用的策略。是"高可用三板斧"（[[限流与熔断|限流]]、[[限流与熔断|熔断]]、降级）之一，通过"丢卒保车"的方式，在系统过载时保证核心服务的可用性。**

### 🧠 第一性原理

"丢卒保车。"  
系统资源有限，当流量超过系统承载能力时，必须做出取舍。  
**本质策略：通过牺牲非核心功能，将有限的资源集中到核心功能上。**

### 🛠️ 落地实现（典型策略）

```
Degradation 的核心策略：

1. 页面降级
   - 静态页面替代动态页面
   - 例如：双11期间，商品详情页返回预渲染的静态页面
   - 减轻数据库压力，保证核心购买流程可用

2. 服务降级
   - 返回默认值或缓存数据
   - 例如：推荐系统故障时，返回默认推荐列表
   - 保证主流程不受影响

3. 功能降级
   - 关闭非必要功能
   - 例如：评论、点赞、推荐功能暂时关闭
   - 将资源集中到下单、支付等核心功能

4. 自动降级 vs 手动降级
   - 自动降级：通过 Sentinel、Hystrix 等框架，根据指标自动触发
   - 手动降级：运维人员通过配置中心手动关闭功能

5. 典型应用
   - 电商大促：关闭评论、推荐，保证下单、支付可用
   - 支付系统：支付失败时，返回友好的错误页面
   - 社交网络：图片加载失败时，显示默认图片
```

### ⚖️ 架构权衡

- **优点**：保证核心功能在系统过载时仍可用；快速恢复服务，减少故障影响范围。
    
- **缺点**：用户体验下降；需要业务方参与设计降级策略。
    
- **大厂实践**：阿里巴巴 Sentinel、Netflix Hystrix 都提供完善的降级机制；电商大促期间通过降级非核心功能，保证核心购买流程的可用性。
